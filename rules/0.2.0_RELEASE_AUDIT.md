# OpenCLScope 0.2.0 – release and head-to-head audit

## Source baselines and result

Immutable inputs and exact source ZIP SHA-256 are recorded in `PRE_PATCH_PARITY_AUDIT.md`. The source baseline is VulkanScope 3.0.12 (856 ZIP entries), VulkanScope Database 1.4.12 (840 entries), plus OpenCLScope 0.1.0 (149 entries). Reference `cl.xml` and official SVG remain byte-identical. This successor adds an explicit database integration without mixing the incompatible Vulkan report/schema into the OpenCL data model.

This is a functional/visual OpenCL adaptation, **not** a claim of byte-for-byte, pixel-for-pixel, or native Vulkan API parity. The requested new public Database is source-complete but not yet live-deployed because no account credentials, D1 UUID or official new endpoint were available. A user building before deployment sees explicit unconfigured state, never a fictitious server.

## Pre-fix oracle and evidence

OpenCLScope 0.1.0 lacks `DatabaseClient.kt`, HTTPS permission and the Worker schema: database submission and lookup cannot occur. OpenCLScope 0.2.0 has the complete producer protocol; `tools/test_database_contract.py` denies missing property mutation, accepts actual successfully queried false scalar, denies offline report submission, and matches the paired Worker fixture. `tools/test_native.py` compiles and executes actual C++ collector with mock loader, Unicode, image formats, no loader, missing symbol, bounds and negative-mutation control. Worker and snapshot tests are runnable from paired Database source and were executed in this environment; static validator confirms resource and query-set identity.
