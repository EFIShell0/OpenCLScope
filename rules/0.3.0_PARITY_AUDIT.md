# OpenCLScope™ 0.3.0 — full reference/parity audit

## Immutable baseline

The exact input archive hashes, file sizes and entry counts are pinned in `BASELINE_AUDIT.md`: VulkanScope 3.0.12 (856 entries), its Database 1.4.12 (840 entries), OpenCLScope 0.2.0 and Database 0.1.0, plus the attached OpenCL SVG/XML. This update did not overwrite the original reference.

## Defect-before-fix evidence (0.2.0)

- Its launcher lacked the reference two-tier **SCOPE** wordmark; 0.3.0 composes the user's official OpenCL logo with exactly the inherited SCOPE glyph source. The byte-identical source resides at `branding/upstream_scope_wordmark_unmodified.png`, SHA-256 `9167a36fe6f31e21d796bc01d42276d1e0f2397193ab6e814133b7bf0dc72ed9`.
- The previous opening animation was a fixed 850 ms delay. This version implements the reference four-stage movement with the live collection and optional update check delayed until completion, and with a Preferences switch.
- Previous Preferences lacked Obtainium and a dedicated runtime/update section. This version offers opt-in GitHub release checks, fixed-source Obtainium app handoff/config share, and an opening-animation toggle. **It cannot be active until the actual published official OpenCLScope GitHub repository is provided as the validated build-time property**. VulkanScope's own repository is not reused.
- Previous app lacked persistent successful History, full local Watch comparison and Analyze Minimum. This version adds them with bounded private report storage, delete confirmation, reliable absent/false state handling, full JSON/TXT/HTML and native import provenance.
- 0.1.0 Worker accepted only producer 0.2.0, rejecting new 0.3.0 reports with HTTP 400. The paired Database 0.2.0 accepts precise 0.2.0/200 and 0.3.0/300 pairs, rejects mixed/incomplete query rows, and preserves historical reports/snapshot hashes.

**Limits:** Not a byte-identical/feature-identical VulkanScope build: native Vulkan-specific workflows and parts of its large analysis/file-manager subsystem have no legitimate OpenCL analogue. No APK/Android 37 or device/TV screenshot tests were run in this container because the Android SDK/NDK and devices are unavailable; no account-bound Cloudflare D1 or GitHub Pages live deployment was carried out. The delivered products are complete source projects and companion backend, not signed APKs or a live website.

## Correctness controls and observed test classification

- PASS: exact Khronos `cl.xml`/`opencl.svg` hashes, 8/120 query keys, 156 nomenclature references, drawable/XML references and three build ABI declarations.
- PASS: new launcher SVG contains official path group and separate converted SCOPE path; byte-for-byte original SCOPE source; mutation that removes the SCOPE path is detected and fails.
- PASS: native C++20 collector host mock covers loader absent, platform absent, actual platform/device/UTF-8/extensions, 18 image-format groups, entry-point errors, bounds and negative mutation/valid control.
- PASS: producer/Worker contract accepts 0.2.0 and 0.3.0, denies mix/version spoof/missing query/offline upload, preserves an actual reported `false` value.
- PASS: 11 Node Worker/snapshot tests: POST/read/duplicate/cursor, malicious origin, chunk damage, snapshot on first insert only, pagination, digest corruption and required report ID guard.
- PASS: v0200 cache-busting Pages asset staging contains only index/config/assets/data/registry, with an empty initial report index (no fabricated reports).
- STATIC/KOTLIN: independent `kotlinc` pass was attempted without Android/Compose dependencies; no Kotlin parser token errors detected, but a real Gradle Android compile is NOT EXECUTED and cannot be claimed from such a partial syntax pass.
- NOT EXECUTED: APK/build/ProGuard, emulator/real GPU Android+all ABIs, UI/animation/TV accessibility, Cloudflare D1 actual mutation, GitHub Releases updates and GitHub Pages live snapshot.
