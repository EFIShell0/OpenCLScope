# OpenCLScope 0.8.1 Kotlin runtime-refresh coroutine fix

## Immutable predecessor
- OpenCLScope 0.8.0 is the immediate predecessor.
- VulkanScope 3.0.12 remains the immutable UI/build/accessibility reference.
- No dependency, SDK, NDK, ABI, registry, branding, collection-schema or query-catalog downgrade is permitted.

## Defect
`UpdatePreferencesPage` exposes `onRefreshRuntime` as a normal `() -> Unit` callback, while the runtime collector is `suspend fun collect()`. OpenCLScope 0.8.0 called `collect()` directly from that non-suspending callback, so `:app:compileReleaseKotlin` failed with `Suspend function 'collect' can only be called from a coroutine or another suspend function`.

## Fix
- Runtime refresh now crosses the coroutine boundary with `scope.launch { collect() }`.
- `collect()` remains suspending and keeps native enumeration on `Dispatchers.IO`; UI-thread blocking collection remains forbidden.
- The callback type remains the VulkanScope-compatible normal click callback; no dependency or API downgrade is used.

## Regression gate
`tools/verify_kotlin_build_regressions.py` now requires the coroutine launch boundary and includes a deliberate negative mutation that restores the direct `collect()` call. The mutation must be rejected.

## Version pair
OpenCLScope 0.8.1 / 801 pairs with OpenCLScope Database 0.7.1 so complete live reports retain exact producer identity and do not fail closed as HTTP 400 solely because of the point release.

## Not executed
A complete Android release APK build is NOT EXECUTED unless the build environment contains the pinned Android SDK 37, NDK 29.0.14206865 and required Gradle artifacts. Device-only D-pad, TalkBack, RTL and high-DPI checks remain NOT EXECUTED here.
