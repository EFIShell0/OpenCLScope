# OpenCLScope 0.6.1 Kotlin release build fix

## Evidence
A real `:app:assembleRelease` build reached `:app:compileReleaseKotlin` after all three native ABI CMake builds and failed on the 0.6.0 sources. The reported failures were invalid `matchParentSize`, pointer `consume`, key/nativeKey event imports, an unsupported `AlertDialog` icon parameter, an out-of-scope `align`, and a direct `weight` import.

## Reference decision
VulkanScope 3.0.12 remains immutable. Its pinned Android/Compose/Gradle versions are unchanged. The fix follows its working Compose API usage instead of changing or downgrading dependencies.

## Fixes
- `matchParentSize`, `weight` and pointer `consume` remain receiver/member operations and are not imported as top-level symbols.
- D-pad handling imports `key` and `nativeKeyCode` exactly as the VulkanScope reference does.
- Long OK/Enter copy behavior uses the VulkanScope 550 ms state-machine approach and no `nativeKeyEvent` import.
- The Database submit shield is rendered inside the dialog title accepted by the local parity wrapper.
- QR centering uses a parent `Box` with `contentAlignment`, not a scope-invalid `Modifier.align` call.

## Regression gate
`python tools/verify_kotlin_build_regressions.py` must pass. It also deliberately reintroduces five failures in memory and requires all five mutations to be rejected.

## Version pairing
OpenCLScope 0.6.1 / 601 pairs with OpenCLScope Database 0.5.1. JNI, Kotlin fallback, Database envelope and Worker producer allowlist use one exact producer identity.

## Not executed
A complete AGP release APK build is NOT EXECUTED unless the build environment has the pinned Gradle/Android SDK/NDK/dependency artifacts. Physical D-pad, TalkBack, RTL and high-DPI validation remain device-only evidence.
