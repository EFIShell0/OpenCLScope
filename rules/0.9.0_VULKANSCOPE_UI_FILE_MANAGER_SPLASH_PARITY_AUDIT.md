## Immutable inputs
- Predecessor: `OpenCLScope-0.8.1.zip`, 248 archive entries, SHA-256 `42b32f4878084ca98e2a2db188ee357b12d7b6dbbd93656116a69067c7a20e50`.
- UI/file-management reference: `VulkanScope-3.0.12.zip`, 856 archive entries, SHA-256 `8ce46a6d67824abd720fe11da3605b1693873f8de2b4be04fe58283b361d1ff2`.

## Pre-patch findings
- Report import/export still used Android `OpenDocument` / `CreateDocument` SAF launchers and content-URI streams.
- The existing OpenCLScope file page was a simplified report action page rather than the VulkanScope full-screen shared-storage browser.
- Device, extension and property filters used simplified selection treatments; Encyclopedia exposed category chips and incremental `Load next` behavior instead of the VulkanScope searchable/paged selector language.
- The opening animation was drawn after the Scaffold/navigation tree, allowing application controls to exist and become visible behind the animation.
- Multi-device selection was embedded only in Devices instead of the common page-level position used by VulkanScope.

## 0.9.0 changes
- Removed SAF launcher/import/export paths and routed report file operations through a full-screen direct shared-storage manager.
- Ported canonical-root enforcement, 4096-entry bounded scans, atomic temp-file replacement, breadcrumb navigation, expandable search, overwrite confirmation, six functional view modes, six sort modes, explicit permission flow, D-pad/page-key and desktop wheel behavior.
- Added a common Expressive searchable/paged selector and applied it to device, extension scope, evidence state, Database mode, Analysis filters and Encyclopedia categories.
- Moved multi-device selection above page content so the active device remains consistent across destinations.
- Made opening animation an exclusive composition gate before network state, Scaffold, header, navigation, banners and page content are created.
- Kept OpenCL-only semantics, the normative `cl.xml` query contract and Vulkan-only feature exclusions unchanged.

## Regression controls
- Static release gate rejects SAF contracts/content streams anywhere in production Kotlin.
- Release gate requires direct shared-storage permission, canonical/atomic File Manager primitives and functional list/grid view implementations.
- UI parity gate requires the common selector in Devices/Encyclopedia/Database/Analysis and rejects restored `FilterChip` selection.
- Startup gate requires `return@MaterialExpressiveTheme` before application chrome/network composition.
- Existing Kotlin gate still rejects the invalid direct call to suspending `collect()`.
