## UI parity closure

## OpenCL 3.1 registry/query closure
- Registry generation derives query names from the normative `cl_platform_info` and `cl_device_info` require groups in the supplied `cl.xml` rather than a hand-picked subset.
- Numeric aliases are deduplicated, yielding 16 platform and 209 device query tokens plus 156 registered extension definitions.
- Runtime query state and OpenCL result code are retained for every row. Registry presence never implies runtime support.
- Known safe scalar/string/array shapes are decoded. Vendor/extension properties whose result shape cannot be established safely from the registry mapping remain opaque byte responses rather than guessed values.
- Platform and device extension strings remain separate runtime evidence.
- Image-format evidence remains scoped to the exact context, access flags and image-object type; 18 bounded query groups are exercised where a device/context path is available.

## Android runtime discovery closure
- Direct loader/carrier probing continues past an opened library that lacks required OpenCL entry points.
- `clIcdGetPlatformIDsKHR` is an eligible fallback when exposed.
- Bounded Android ICD vendor-file discovery checks Khronos/vendor locations and rejects path traversal.
- Missing/inaccessible loader, no platform, no device, query error, queried false and not-applicable remain distinct.

## Database compatibility

- Exact historical 0.2.0–0.7.0 producer/version pairs retain their locked 8+120 report contract and are not silently rewritten.
- Imported, partial, loader-unavailable, failed and no-device reports remain ineligible for fresh submission.
