# OpenCLScope 0.8.0 VulkanScope runtime/UI parity audit

## Failing-before-fix oracle
The supplied Android screenshot from OpenCLScope 0.6.1 shows the predecessor using a bespoke Overview body with a large OpenCLScope logo, OpenCL-specific primary presentation that does not match the VulkanScope 3.0.12 Overview hierarchy, and a runtime result of `Unavailable` / native error `-1`. The predecessor manifest requested only `libOpenCL.so` and `libGLES_mali.so`, while Android 12+ restricts access to vendor-provided non-NDK shared libraries unless they are explicitly declared.

## Reference boundary
VulkanScope 3.0.12 remains the immutable UI/navigation/accessibility/build/update/report/Analysis/licensing/file-management/security reference. OpenCL API semantics, OpenCL branding and the green accent family are the only intentional differences. Vulkan Surface/WSI, Turnip and Vulkan Video are never fabricated.

## Runtime repair
- Manifest requests `libOpenCL.so`, `libOpenCL-pixel.so`, `libOpenCL-car.so`, `libOpenCL_adreno.so`, `libGLES_mali.so`, `libmali.so` and `libPVROCL.so` as optional vendor native libraries.
- Loader discovery tries Khronos Android ICD naming first, then known device carriers and bounded legacy paths.
- A library that can be opened but does not expose the required OpenCL core entry points is closed and discovery continues.
- Loader absence, visible-but-invalid carrier, no platform, query error and actual queried false values remain distinct states. No unavailable path is presented as proof that the GPU lacks OpenCL support.

## UI parity repair
- Common drawable set remains 92/92 byte-identical to VulkanScope 3.0.12.
- Overview hero uses the same 82 dp vendor-logo card geometry and the VulkanScope Overview section ordering; the obsolete giant body logo path is removed.
- Bottom navigation keeps the same four-slot geometry, timings and icons. `OpenCL` replaces Vulkan API semantics; `Devices` occupies the Vulkan Surface slot because OpenCL has no Vulkan WSI/Surface concept.
- Settings preserves Info → Reports & Database → Runtime & Update Preferences ordering; Info, licenses, Analysis workspace, Encyclopedia, GPU logos, transient banners, scroll arrows, D-pad, TalkBack, RTL and high-font/high-DPI behavior remain gated.

## Registry/specification source
The supplied `cl.xml` is bundled byte-identically and regenerated locally into the checked-in query and Encyclopedia assets. Generation validates 8 platform queries, 120 device queries and 156 registered extension definitions. Registry presence is reference metadata only; runtime support comes exclusively from live OpenCL queries and runtime extension enumeration.
